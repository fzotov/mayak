## 3. Запуск и деплой

Локально (через `.claude/launch.json`, конфигурации `dev` и `site`):

```bash
pnpm dev                   # админка и кабинет, http://localhost:5173
pnpm --dir apps/site dev   # сайт, http://localhost:3000
```

Деплой админки. Обычный `vercel --prod` НЕ переключает адрес `mayak-xi.vercel.app`, поэтому всегда три шага. `vercel pull` перед сборкой НЕ запускать: секретные переменные скачиваются как строка `[SENSITIVE]`, сборка получает её вместо адреса Supabase и на проде белый экран (так было 23.11.2026). Сборка берёт `VITE_*` из `.env.local`; если файл `.vercel/.env.production.local` появился — удалить.

```bash
export VERCEL_TOKEN=$(grep '^VERCEL_TOKEN=' .env.local | cut -d= -f2)
npx vercel build --yes --target production
npx vercel --prod --yes --prebuilt        # в выводе будет новый адрес admin-XXXX-vizbl.vercel.app
npx vercel alias admin-XXXX-vizbl.vercel.app mayak-xi.vercel.app
```

## 6. Как устроено (то, что не видно сразу из кода)

- Маршрутизация в `src/main.tsx`: путь начинается с `/tenant` → `TenantApp`, иначе `AdminApp`. Внутри `TenantApp` свой ручной роутер по `window.location.pathname`.
- Шрифт Geist подключён через `src/index.css` (Google Fonts), файл импортируется в `main.tsx`. Без этого импорта шрифт не грузится.
- Вход (с 23.11.2026): и сотрудники, и арендаторы — пользователи Supabase Auth. Сотрудник = строка в `profiles` (роль `owner` / `manager`), арендатор = строка в `tenant_users` (привязка к `tenant_id`). Свободной регистрации нет: владелец приглашает сотрудника из окна профиля (левый нижний угол), арендатора приглашают из его карточки, вкладка «Общие».
- Приглашение и сброс пароля — одноразовые ссылки из таблицы `auth_tokens` (в базе только SHA-256 токена; приглашение 7 дней, сброс 2 часа). Страницы `/tenant/activate?token=` и `/tenant/reset-password?token=`, функция `api/set-password.js`. Таблица `tenant_portal_access` больше не используется.
- Сотрудников двое: владелец и управляющая (Фёдор, 23.11.2026). Роли в `profiles`: `owner` и `manager`, база других не принимает. Оба видят и ведут всё; выдавать и отзывать доступ может только владелец (окно профиля в левом нижнем углу).
- RLS включён на всех таблицах (`supabase/migrations/20261123_security.sql`): без входа доступна только вставка в `site_leads`; сотрудник видит всё; арендатор читает только строки своего `tenant_id`. Новую таблицу нужно добавлять вместе с политикой, иначе её не увидит никто, кроме service key.
- Каждая функция в `api/` начинается с `requireStaff` или `requireTenant` из `api/_lib/auth.js`; клиент вызывает их через `apiFetch` (`src/lib/api.ts`), который подставляет токен входа. Публичных функций три: `set-password`, `request-password-reset`, `approve-invoice` — они защищены одноразовыми токенами.
- Бакеты `invoices`, `meter-photos`, `tenant-documents` закрытые; файл открывается по временной ссылке (`openStoredFile`). `unit-media` публичный — фото для сайта.
- Адреса страниц админки (с 25.11.2026, этап 5) — обычные пути на react-router: `/tenants/<id>`, `/settlements/<id>`, `/invoices/<id>`, `/contracts/<id>`, `/debtors`, `/bank?tab=unrec`. Таблица маршрутов и меню — `src/App.tsx`. Кабинет арендатора — `/tenant` и `/tenant/…` (проверка в `src/main.tsx` именно так, иначе `/tenants` уходил бы в кабинет). Старые ссылки `/#/tenant-card/<id>` переводятся на новые сами (`src/lib/nav.ts`). Переход из кода — `go('/путь')` из `src/lib/nav.ts`, в разметке — `Link` из `ui.tsx`. На Vercel все пути отдают `index.html` (`vercel.json`).
- Оформление: токены цветов в `src/index.css` (светлая и тёмная тема, `data-theme` на `<html>`), компоненты — `src/components/ui.tsx` (цвета только через `C`, без шестнадцатеричных значений). Тема админки переключается кнопкой рядом с профилем (светлая / тёмная / как в системе, хранится в браузере). Кабинет арендатора всегда в тёмной теме той же палитры.

Общий поиск в шапке (Ctrl/⌘+K) — арендаторы, ИНН, офисы, счета, договоры. «Должники» (`src/pages/Debtors.tsx`) — по функции `tenant_saldo()`, действия: напоминание (`api/send-reminder.js`), акт сверки, претензия.

- Статус помещения `units.status` (`free` / `occupied`) выводится из `tenants.unit_number` — это текст, в котором может быть несколько номеров и составные вроде `201.202` (такой номер есть в `units` и целиком, и по частям). Кириллические А/Б в номерах приводятся к латинским A/B.
- Служебные помещения заняты всегда: 228 (кухня), 301 и 302 (офис управляющей компании), 326 (склад), 326А, 326Б (МФЦ).

- Прод-адрес для ссылок в письмах берётся из переменной `APP_URL` (по умолчанию `https://mayak-xi.vercel.app`).
- Учётное ядро (этап 2, `supabase/migrations/20261125_accounting_core.sql`). Документы: `charges` (начисление по статье), `payments` (поступление или возврат), `allocations` (разнесение: какая сумма из какой оплаты или депозита закрыла какое начисление), `deposit_operations`. Регистр `ledger_postings` с тремя регистрами: `receivable` — расчёты по статьям, `advance` — неразнесённые деньги, `deposit` — депозиты по договорам. Баланс арендатора = долг по статьям − аванс; депозит в долг не входит.
- Писать в `charges`, `payments`, `invoices`, `allocations`, `ledger_postings` может только функция базы: `post_payment`, `post_charge`, `storno_charge`, `storno_payment`, `cancel_allocation`, `allocate_manual`, `deposit_require`, `deposit_offset`, `refund`, `post_opening_balance`, `billing_post`. У сотрудника на эти таблицы только чтение, триггер запрещает менять и удалять проведённое — исправление только сторно. Оплата сама гасит открытые начисления: сначала с более ранним сроком, при равном — по очереди статьи (`accounting_articles.priority`).
- Договоры — таблица `leases` (единственная; `contracts` и `tenant_contracts` пусты и остались только для старой синхронизации с 1С), ежемесячные начисления — строки `lease_lines` со статьёй, суммой и периодом действия. Смена ставки — новая строка, старая закрывается датой. Биллинг (`billing_lines` — предпросмотр, `billing_post` — проведение) считает неполный месяц по дням, коммунальные — по `meter_readings` за месяц, тепло — по `heat_bills.items`, пени — если включены в договоре; ключ `billing_key` не даёт провести одно и то же дважды.
- Самопроверка `verify_ledger()` пересчитывает остатки из документов и сравнивает с регистром; при расхождении на сводке появляется красная строка. Отчёты: `ledger_turnover(from, to, tenant)` — обороты, представления `v_charge_state`, `v_payment_state`, `v_invoice_state` (статус оплаты счёта вычисляется), `v_deposits`, `v_tenant_documents`.
- Экраны: «Расчёты» (`src/pages/Settlements.tsx`: оборотная ведомость, депозиты, статьи, самопроверка, карточка расчётов арендатора с операциями и актом сверки), «Счета» (печать с QR по ГОСТ, отправка письмом и в кабинет — `api/send-invoice.js`), «Биллинг», «Договоры». Общие элементы админки — `src/components/ui.tsx`.
- Банк (этап 4, `supabase/migrations/20261126_bank.sql`). Выписка грузится файлом из СберБизнес («Выписка» → «Экспорт» → «в 1С», `kl_to_1c.txt`, Windows-1251); разбор — `src/lib/clientBank.ts`, без ИИ. Функция `bank_import` пишет файл в `bank_statement_files` (контрольная сумма — второй раз тот же файл не загрузить; сверка «остаток + обороты = остаток» и «документы = обороты банка»), операции — в `bank_transactions` (ключ `bank_key`, повтор операции пропускается) и сразу зачисляет поступления (`bank_credit`). Арендатор определяется по порядку: ИНН плательщика → номер счёта в назначении → номер договора в назначении → плательщик, привязанный вручную (`bank_payer_links`). Не найден — статус `unrecognized`, очередь «Банк → Не распознано»: оператор выбирает арендатора (`bank_assign`, плательщик запоминается) или отмечает «не от арендатора» (`bank_ignore`). ИИ (`api/match-transactions.js`) только подсказывает.
