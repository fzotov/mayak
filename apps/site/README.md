# Сайт БЦ «Маяк» — mayak-d.ru

Публичный сайт бизнес-центра: каталог помещений, интерактивные планы 2 и 3 этажей,
страницы офисов и заявки на просмотр.

Next.js 16 (App Router) · React 19 · TypeScript · Tailwind CSS 4.

```bash
npm --prefix apps/site run dev     # разработка, http://localhost:3000
npm --prefix apps/site run build   # прод-сборка
npm --prefix apps/site run lint    # проверка ESLint
```

Пакет использует npm со своим `package-lock.json` — так его собирает Vercel.
Остальной монорепозиторий остаётся на pnpm.

## Как устроены данные

Геометрия и бизнес-данные разделены:

| Файл | Что хранит |
|------|------------|
| `data/floors.ts`  | контуры помещений и подложки схем этажей (точные пути из исходных схем) |
| `data/offices.ts` | номера, площади, статусы, цены, фотографии, кадастровые номера |
| `data/redirects.ts` | карта 301-редиректов со старого сайта |

Связь — по идентификатору: `Office.svgRoomIds` содержит id полигонов на схеме
(`room-217`, для объединённых помещений — несколько: `["301", "302"]`).
Поэтому изменение статуса или цены не требует правки схемы, а правка схемы — правки данных.

Смена статуса в `data/offices.ts` автоматически меняет: подсветку на плане, карточку офиса,
фильтры, страницу помещения и блок «Актуальные предложения» на главной.

Весь доступ к данным идёт через `lib/offices.ts` (`getOffices`, `getOffice`, …).
Чтобы перевести сайт на API или Supabase, достаточно поменять реализацию этих функций —
компоненты не знают, откуда приходят данные.

## Схемы этажей

`public/floorplans/floor-2.png`, `floor-3.png` — подложки, `floor-2.svg` — исходная схема 2 этажа.
Геометрия не перерисовывалась: контуры помещений перенесены из исходных схем как есть,
подрезка полей делается через `cropViewBox`, координаты при этом не меняются.

## Заявки

`POST /api/lead` — honeypot, валидация телефона, ограничение 5 заявок с IP в час.
Заявки уходят в таблицу `site_leads` Supabase (та же база, что у системы управления зданием)
и, если заданы переменные, дублируются в Telegram. Переменные окружения — в `.env.example`.

Порядок доставки заявки:

1. таблица `site_leads` — основное хранилище, видно в админке в разделе «Сайт и заявки»;
2. если таблицы ещё нет — задача в таблице `tasks` с пометкой «Заявка с сайта» и приоритетом
   «высокий», видна в админке в разделе «Все задачи» (нужен `SUPABASE_SERVICE_KEY`);
3. Telegram, если заданы `TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_ID`.

Если не сработал ни один канал — ответ 502, и посетителю предлагается WhatsApp с заполненным
сообщением и телефон, то есть обращение не теряется молча. Как только выполните
`supabase/migrations/20260920_site.sql`, заявки начнут падать в `site_leads`, а запасной канал
перестанет использоваться сам собой.

`SUPABASE_SERVICE_KEY` используется только на сервере (в API-маршруте) и в браузер не попадает.

## Деплой

Проект Vercel: **vizbl/mayak-site**, продакшен — https://mayak-site.vercel.app.
Деплой из папки: `npx vercel --prod` (папка уже связана через `.vercel`).
Переменные `SUPABASE_URL` и `SUPABASE_ANON_KEY` заданы в проекте для всех сред.
Редиректы со старых адресов описаны в `next.config.ts` и работают автоматически.
Домен mayak-d.ru пока не подключён — он остаётся на старом хостинге.

## SEO

- уникальные `title`/`description`/`canonical` и Open Graph на каждой странице;
- разметка `RealEstateAgent` на сайте и `Product` на страницах помещений;
- `sitemap.xml` и `robots.txt` генерируются автоматически;
- 301-редиректы со всех старых адресов (`/rent.html`, `/office.html?id=N`, …) — в `next.config.ts`;
- события для Яндекс.Метрики (счётчик 31410123) — `lib/analytics.ts`.
